# Vitest Migration — PR #1: Infra Alongside Jest

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Land Vitest in the frontend without removing Jest. CI runs both. One smoke test passes on Vitest. Zero behavior change for Jest.

**Architecture:** Add `vitest.config.ts` and `vitest.workspace.ts` next to the existing `jest.config.js`. Wire pnpm scripts (`test:vitest`, `test:vitest:coverage`). Add a CI job that runs Vitest in parallel with the existing Jest job. Defer all test-file rewrites to PR #2.

## Task 2: Add `vitest.config.ts`

**Files:**

- Create: `frontend/vitest.config.ts`

**Step 1: Write the config**

```ts
// frontend/vitest.config.ts
import { defineConfig } from "vitest/config";
import react from "@vitejs/plugin-react";
import tsconfigPaths from "vite-tsconfig-paths";

export default defineConfig({
  plugins: [react(), tsconfigPaths()],
  test: {
    environment: "jsdom",
    setupFiles: ["./src/test/setup.ts"],
    globals: false,
    css: { modules: { classNameStrategy: "non-scoped" } },
    testTimeout: 15_000,
    clearMocks: true,
    restoreMocks: true,
    coverage: {
      provider: "v8",
      reporter: ["text", "html", "lcov", "json-summary"],
      reportsDirectory: "./coverage",
      include: [
        "src/components/**/*.{ts,tsx}",
        "src/hooks/**/*.{ts,tsx}",
        "src/services/**/*.{ts,tsx}",
        "src/store/**/*.{ts,tsx}",
        "src/utils/**/*.{ts,tsx}",
      ],
      exclude: [
        "src/**/*.d.ts",
        "src/**/*.stories.{ts,tsx}",
        "src/**/index.{ts,tsx}",
        "src/components/ui/**",
      ],
      // Match Jest's current floor for PR #1; PR #5 raises this.
      thresholds: { lines: 8, branches: 7, functions: 7, statements: 8 },
    },
    reporters: process.env.CI
      ? ["default", ["junit", { outputFile: "coverage/junit-vitest.xml" }]]
      : ["default"],
  },
});
```

**Why these defaults are fixed:**

- `globals: false` — explicit imports beat implicit globals; survives stricter TS configs
- `clearMocks` + `restoreMocks` — mirrors current Jest behavior so codemod in PR #2 has identical semantics
- `junit-vitest.xml` (not `junit.xml`) — keeps Jest's existing artifact untouched while both runners run in parallel

**Step 2: Type-check the config**

```bash
cd frontend && pnpm exec tsc --noEmit -p tsconfig.json
```

Expected: no new errors mentioning `vitest.config.ts`. If `tsconfigPaths` complains, the `tsconfig.json` paths block is fine — Vitest reads it via the plugin.

**Step 3: Commit**

```bash
cd ..
git add frontend/vitest.config.ts
git commit -m "chore(frontend): add vitest.config.ts (jsdom, v8 coverage, junit reporter)"
```

## Task 3: Add `vitest.workspace.ts` for unit + cli split

**Files:**

- Create: `frontend/vitest.workspace.ts`

**Step 1: Write the workspace**

```ts
// frontend/vitest.workspace.ts
import { defineWorkspace } from "vitest/config";

export default defineWorkspace([
  {
    extends: "./vitest.config.ts",
    test: {
      name: "unit",
      environment: "jsdom",
      include: ["src/**/__tests__/**/*.test.{ts,tsx}"],
      exclude: [
        "src/integration/**",
        "src/__tests__/App.routing.test.tsx",
        "node_modules/**",
        "e2e/**",
      ],
    },
  },
  {
    extends: "./vitest.config.ts",
    test: {
      name: "cli",
      environment: "node",
      include: ["cli/__tests__/**/*.test.{ts,tsx}"],
      exclude: ["node_modules/**"],
    },
  },
]);
```

**Why:** CLI tests rely on `process` IO and don't need a DOM. Forcing both into jsdom is the #1 cause of flaky CLI tests.

**Step 2: Commit**

```bash
git add frontend/vitest.workspace.ts
git commit -m "chore(frontend): add vitest workspace splitting unit (jsdom) from cli (node)"
```

## Task 4: Create the test setup file

**Files:**

- Create: `frontend/src/test/setup.ts`

**Step 1: Port the existing setup**

The current `src/setupTests.ts` has polyfills (TextEncoder, TransformStream, PerformanceObserver) and Supabase env mocks. Mirror them for Vitest.

```ts
// frontend/src/test/setup.ts
import "@testing-library/jest-dom/vitest";
import { TextEncoder, TextDecoder } from "util";
import { TransformStream as WebTransformStream } from "node:stream/web";

// Polyfills missing in jsdom
Object.assign(globalThis, { TextEncoder, TextDecoder });

const g = globalThis as unknown as {
  TransformStream?: typeof globalThis.TransformStream;
  PerformanceObserver?: typeof globalThis.PerformanceObserver;
};

if (typeof g.TransformStream === "undefined") {
  g.TransformStream =
    WebTransformStream as unknown as typeof globalThis.TransformStream;
}

if (typeof g.PerformanceObserver === "undefined") {
  class MockPerformanceObserver {
    static readonly supportedEntryTypes: string[] = [];
    observe(): void {}
    disconnect(): void {}
    takeRecords(): PerformanceEntryList {
      return [];
    }
  }
  g.PerformanceObserver =
    MockPerformanceObserver as unknown as typeof globalThis.PerformanceObserver;
}

// Mirror existing Supabase test env behavior from src/setupTests.ts.
// Without this the Supabase client module throws at import in tests.
if (!process.env.NEXT_PUBLIC_SUPABASE_URL) {
  process.env.NEXT_PUBLIC_SUPABASE_URL = "http://localhost:54321";
}
if (!process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY) {
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY = "test-anon-key";
}
```

**Why no MSW yet:** PR #3 wires MSW. PR #1 must be a runner swap only — adding MSW here would make the diff harder to review and conflate two changes.

## Task 7: Wire Vitest into CI

**Files:**

- Modify: `.github/workflows/fast-ci.yml`

**Important:** the existing `test-frontend` job in `fast-ci.yml` uses `npm install` and `npm test` — that is **wrong** per project memory (`pnpm-lock.yaml` is the only committed lockfile). Do not propagate that mistake. New job uses pnpm.

**Step 1: Add a `test-frontend-vitest` job**

Add this job under `jobs:` after `test-frontend`:

```yaml
test-frontend-vitest:
  name: Frontend Tests (Vitest)
  runs-on: ${{ github.event.inputs.runner || vars.FAST_CI_RUNNER || 'ubuntu-latest' }}
  continue-on-error: true # PR #1 only; PR #2 makes it required.
  steps:
    - uses: actions/checkout@v6

    - name: Setup pnpm
      uses: pnpm/action-setup@v4
      with:
        version: 9

    - name: Setup Node
      uses: actions/setup-node@v4
      with:
        node-version: "20"
        cache: "pnpm"
        cache-dependency-path: frontend/pnpm-lock.yaml

    - name: Install
      working-directory: frontend
      run: pnpm install --frozen-lockfile

    - name: Run Vitest
      working-directory: frontend
      run: pnpm test:vitest

    - name: Upload JUnit
      if: always()
      uses: actions/upload-artifact@v4
      with:
        name: vitest-junit
        path: frontend/coverage/junit-vitest.xml
        if-no-files-found: ignore
```

**Step 2: Update the summary job to include the new job**

Find the `summary` job's `needs:` list and add `test-frontend-vitest`:

```yaml
summary:
  name: CI Summary
  runs-on: ${{ github.event.inputs.runner || vars.FAST_CI_RUNNER || 'ubuntu-latest' }}
  needs: [lint, test-backend, test-frontend, test-frontend-vitest]
```

**Step 3: Validate the YAML locally**

```bash
pnpm dlx @actions/dependabot-action-yaml-validator .github/workflows/fast-ci.yml || \
  python3 -c 'import yaml,sys; yaml.safe_load(open(".github/workflows/fast-ci.yml"))' && echo OK
```

Expected: `OK`. If parse fails, fix indentation before committing — GitHub's web validator is fine but slow.

**Step 4: Commit**

```bash
git add .github/workflows/fast-ci.yml
git commit -m "ci(frontend): add Vitest job alongside Jest (continue-on-error during PR #1)"
```
