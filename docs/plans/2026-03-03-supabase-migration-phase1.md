# Supabase Migration Phase 1: Database Connection Swap

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Swap PostgreSQL from local Docker container to Supabase-managed PostgreSQL (via Supabase CLI locally), with zero changes to models or queries.

**Architecture:** Keep all 63 SQLAlchemy models and the entire service layer intact. Only change the connection plumbing in `database.py`, `config.py`, env files, and Docker Compose. Supabase CLI provides a local PostgreSQL instance that matches production.

**Tech Stack:** Supabase CLI, PostgreSQL 15, asyncpg, SQLAlchemy (async), FastAPI

### Task 4: Update database.py for Supabase Connection

**Files:**

- Modify: `backend/src/core/database.py:27-38` (connection string), `79-87` (async engine)

**Step 1: Update DATABASE_URL resolution**

In `backend/src/core/database.py`, replace lines 27-38 with logic that prefers `SUPABASE_DB_URL` when set:

```python
# Database URL resolution: prefer SUPABASE_DB_URL if set
_supabase_db_url = os.getenv("SUPABASE_DB_URL", "")
DATABASE_URL = _supabase_db_url or os.getenv(
    "DATABASE_URL",
    "postgresql://postgres:postgres@localhost:5432/multimodal_rag_dev",
)

# Async variant
if "asyncpg" not in DATABASE_URL:
    ASYNC_DATABASE_URL = DATABASE_URL.replace(
        "postgresql://", "postgresql+asyncpg://"
    )
else:
    ASYNC_DATABASE_URL = DATABASE_URL
```

**Step 2: Add PgBouncer compatibility to async engine**

Supabase uses PgBouncer in transaction mode, which doesn't support prepared statements. In the async engine creation (around line 79), add `prepared_statement_cache_size=0` to the connect_args:

```python
async_engine = create_async_engine(
    ASYNC_DATABASE_URL,
    pool_size=10,
    max_overflow=20,
    pool_timeout=30,
    pool_recycle=300,
    pool_pre_ping=False,
    connect_args={
        "prepared_statement_cache_size": 0,
        "statement_cache_size": 0,
    },
)
```

Note: `statement_cache_size=0` is needed for asyncpg with PgBouncer transaction mode.

**Step 3: Add SSL support for production Supabase**

After engine creation, add a note/conditional for production SSL:

```python
# For production Supabase: append ?sslmode=require to DATABASE_URL
# Local Supabase CLI does not require SSL
```

This is documentation only for Phase 1 — SSL will be configured when deploying to cloud Supabase.

**Step 3: Create Supabase client utility**

Create `backend/src/core/supabase_client.py`:

```python
"""Supabase client initialization."""

import structlog
from supabase import create_client, Client

from src.core.config import settings

logger = structlog.get_logger(__name__)

_supabase_client: Client | None = None


def get_supabase_client() -> Client | None:
    """Get or create the Supabase client singleton."""
    global _supabase_client
    if _supabase_client is not None:
        return _supabase_client

    if not settings.SUPABASE_URL or not settings.SUPABASE_SERVICE_ROLE_KEY:
        logger.warning("supabase_not_configured", msg="SUPABASE_URL or SUPABASE_SERVICE_ROLE_KEY not set")
        return None

    try:
        _supabase_client = create_client(
            settings.SUPABASE_URL,
            settings.SUPABASE_SERVICE_ROLE_KEY,
        )
        logger.info("supabase_client_initialized", url=settings.SUPABASE_URL)
        return _supabase_client
    except Exception as exc:
        logger.error("supabase_client_init_failed", error=str(exc))
        return None
```

This will be used in Phase 2+ for Auth, Storage, etc. For Phase 1 it just needs to exist.
