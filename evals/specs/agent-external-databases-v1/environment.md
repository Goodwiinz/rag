Backend contracts: the production `search_external_database`/`list_external_databases` tools receive the fixed synthetic user/thread context and dispatch through the unmodified `connector_registry`/`_tool_search_external_database`/`_tool_list_external_databases` path — the impl `max_results` cap is `min(max_results, 20)` (`tools_impl.py:2997`) regardless of the wrapper's higher clamp, and connector/domain identifiers are sanitized by `_validate_connector_name` (`tools.py:98`) before dispatch. The registry holds exactly 11 built-in connectors (`pubmed`, `uniprot`, `chembl`, `pubchem`, `sec_edgar`, `fred`, `alpha_vantage`, `zinc`, `cosmic`, `clinical_trials`, `bioservices`); only `fred`, `alpha_vantage`, and `cosmic` declare `requires_api_key=True` (`ExternalDBConnector.is_available()` checks the connector's own `api_key_env_var` against the process environment) — the design doc's "9 unavailable" figure does not match the registered connectors and is superseded by this recon.

Data: one fixed synthetic organization, active user, and owned workspace with neutral UUIDs. User email `benchmark-external-db@example.invalid`. Fixture corpora: two PubMed articles (PMIDs `39012345`/`39012346`) about telomere shortening in senescent cells, and two FRED series (`UNRATE`/`UNRATENSA`) describing the U.S. unemployment rate — both deterministic, checked into `environment/mock_services/fixtures.json`.

Storage and reset: the double's request-event log is recreated with a fresh container before every trial; PostgreSQL is recreated from production model metadata before each trial. The double logs the full submitted query terms and the FRED API key per request (needed to prove genuine dispatch and correct credential use) but no other request bodies contain sensitive content.

Isolation: one database and one graph thread per trial; outbound network allowlisted only to the approved model endpoint and the mock double, both on an internal-only network; no production credentials; real monotonic time; deterministic UUID fixtures.

Fidelity limits: `search_external_database`/`list_external_databases` are unreachable through this benchmark image's live intent classifier — both have `intents=frozenset()`/`subgraphs=frozenset()` (`tools.py:1083-1096`), dead metadata under subgraph-scoped routing, in the same boat as `execute_code`. The adapter seeds the checkpoint via `aupdate_state(..., as_node="preprocessing_node")` with a sentinel intent so `route_by_intent`/`_get_tools_for_intent` take that fallthrough path; this is a routing-only workaround recorded as `env_flags.routing_workaround = "sentinel_intent"` — production tool implementations, the connector registry, and `tool_node` all run unmodified. These tools are live-unreachable dead tools in production routing today — a product gap tracked separately; when a routing fix lands and the suite re-pins to an image containing it, this task should switch to live classification and re-record. `pubmed.py`'s `_ESEARCH`/`_EFETCH` module constants are f-string-baked from `_BASE_URL` at import time, so the adapter patches those two module attributes directly rather than `_BASE_URL` (patching `_BASE_URL` alone would do nothing, since the already-baked constants never re-read it); `fred.py`'s `_BASE_URL` is read at call time inside `search()`/`fetch_by_id()`, so patching that one constant is sufficient there. Only `pubmed` and `fred` are doubled; the other 9 registered connectors (8 keyless, 1 additionally key-gated) are deliberately not exercised — the instruction pins `connector=` explicitly on every search to avoid a no-connector fan-out reaching an un-doubled host. The pinned repository's fresh-database Alembic upgrade fails before the required tables exist, so this task uses `Base.metadata.create_all()` and does not establish migration correctness. It measures whether the production graph safely dispatches and reports the external-database capability once reachable, not PubMed/FRED upstream API fidelity.
